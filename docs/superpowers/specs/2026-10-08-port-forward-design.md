# 本地 TCP 端口转发设计

## 目标与范围

在应用中管理多条本地 TCP 端口转发规则。应用监听本机端口，接受连接后直接连接配置的目标主机和端口，再双向转发数据。出站连接使用操作系统现有路由。此功能不使用 SSH 隧道，也不创建或修改操作系统 NAT、路由或端口代理规则。

首版提供规则新增、编辑、删除、手动启动和停止。配置持久化；应用重启后规则保持停止，避免未确认时重新占用本机端口。运行状态和活动连接数属于热数据，显示在设置窗口的“端口转发”页。

## 规则与运行状态

每条规则包含稳定的规则 ID、本机监听 IP、本机监听端口、目标主机和目标端口。目标主机支持 DNS 名称或 IP 地址。

本机监听 IP 默认 `127.0.0.1`，端口默认 `8080`。监听 IP 必须是 IPv4/IPv6 字面量，端口必须在 `1..=65535`。目标主机不能为空，目标端口必须在 `1..=65535`。规则只有停止时才能编辑或删除。

运行状态至少包含规则 ID、是否运行、实际监听地址、活动连接数和最近错误。DataContext 只保存运行状态，不保存规则配置。

## 交互流程

设置窗口增加“端口转发”导航项。页面列出规则的本机端点、目标端点、运行状态和活动连接数。新增/编辑表单提供本机监听地址/端口和目标主机/端口；默认监听地址为 `127.0.0.1`。每条停止中的规则显示“启动”，运行中的规则显示“停止”；运行中的规则禁用编辑和删除。删除前要求用户确认。

保存和运行操作经 Application 完成。GUI 的网络和配置读写操作使用 `cx.spawn` 和 `tokio::spawn`，窗口状态更新回 GPUI 执行。状态变化通过 DataContext 通知刷新页面。错误显示在对应规则附近，保留可读的失败原因。

## 架构与数据流

1. `domain/port_forward.rs` 定义可序列化规则和运行状态类型。
2. `infrastructure/port_forward/` 管理 JSON 配置文件、监听器和转发任务。`mod.rs` 声明子模块并构造 Controller；`core.rs` 管理规则和运行资源生命周期；`external.rs` 提供 InfrastructureContext 使用的具体入口；`relay.rs` 负责单个 TCP 连接的转发。
3. Infrastructure 提供规则配置读写、启动/停止、运行状态订阅和统一关闭入口。每条运行规则拥有独立的 `TcpListener` 与受限的连接任务集合。
4. Application 校验规则字段，编排规则增删改查、启动/停止和状态发布。被运行中规则占用的本机端点不能重复启动；运行中的规则不能编辑或删除。
5. DataContext 存储并发布热运行状态。GUI 通过 Application 操作规则和生命周期，通过 DataContext Reader 读取状态。

持久化读写遵循 `GUI/MCP → Application → Infrastructure` 数据路径；Infrastructure 只提供底层文件和网络能力，规则校验留在 Application。实现不新增 trait 或依赖。

## 转发与生命周期

启动规则时，Infrastructure 绑定本地 `TcpListener`；绑定成功后进入运行状态。每次接受连接时，后台任务使用 `TcpStream::connect` 直连目标地址，然后通过 `tokio::io::copy_bidirectional` 双向复制转发字节流。DNS 解析和目标连接遵循系统网络栈及其路由表。

单个目标连接失败或客户端断开只结束该连接，不停止监听规则；监听器发生错误会关闭该规则并发布错误。每条规则最多处理 128 个并发连接；超出上限时拒绝新连接并记录日志。停止规则时关闭监听器、收拢活动转发任务并发布停止状态。应用退出时统一停止所有规则。启动失败时关闭已创建资源，规则保持停止状态并发布错误。

本机端口被占用、地址格式错误、目标 DNS 解析失败、目标不可达或连接被拒绝等错误均返回可读信息。对单个目标连接的失败保留为规则最近错误并记录日志，用户可继续使用监听器接受后续连接。

日志包含规则 ID、监听地址、目标地址、活动连接数和失败原因，不记录连接负载数据。

## 持久化与启动行为

规则列表保存到 `data/port_forward.json`。更新通过 Application 校验后交给 Infrastructure 写入。应用启动时加载规则并发布初始停止状态，不自动监听；GUI 打开后读取规则列表，用户可逐条启动。保存失败时报告错误，不把未保存配置显示为成功。

## 验收与验证

- GUI 可以新增、编辑、删除多条规则，配置在重启后仍可读取。
- 空目标主机、无效监听 IP、无效端口和编辑/删除运行中规则均由 Application 拒绝，并给出明确原因。
- 用户可通过本地 TCP 客户端连接监听端口并访问目标服务；多个连接可并发转发。
- 端口占用、目标解析失败、目标拒绝连接和监听器错误均能显示；单个目标连接失败不会停止整条规则。
- 停止一条规则不影响其他规则；应用退出清理所有监听器与连接任务。
- 本机监听默认仅绑定回环地址；其他地址需由用户明确配置。
- 按项目要求不新增测试用例。验证使用格式检查、离线编译/构建和手工联调，覆盖正常转发、并发连接、冲突端口、无效目标、停止及重启后的配置读取。

## 约束

- GUI 线程不执行网络或文件 IO；异步操作经 GPUI `cx.spawn` 与 Tokio 执行。
- GUI 按项目 Tailwind CSS 风格约束视觉层次和交互状态；图标优先复用项目已有 Lucide 图标资源。
- 单个 Rust 文件控制在 600–800 行；超过 800 行时按职责拆分目录文件。
- 项目已依赖 Tokio 1.49 并启用 `full` 特性，使用其 TCP 与双向复制 API；不引入 `windows-rs` 或其他转发依赖。
- 不新增测试用例、trait 或依赖。
